Instacart Catalog · A three-year vision · Michael Fitzpatrick

A catalog that shoppers and their agents can trust

Catalog is the platform every other surface stands on. Search, replacements, health filters and now shopping agents all read the same product facts. Over three years I would make those facts measurably correct, then build on that foundation until agents can query them and cite the evidence.

North starTrusted coverageThe share of attribute values that shoppers and agents actually see which meet the quality bar for their family, weighted by views.
The road

Three years, three stages

Each year builds on the last. Targets are proposals until they are set against measured baselines.

1
Year one

Trust the facts

Make the attributes that can hurt someone measurably right, and make every value explain itself.

  • Hand-labeled golden sets for allergens and medical diets, used as the release gate
  • Every value records which source won and why, at the moment it is written
  • An attribute card for each family: definition, owner, freshness and confidence
Year-one targetAllergen values verified on 90% of the items shoppers view, at 99.5% precision
2
Year two

Make attributes cheap

Turn each new attribute from a hand-built project into a repeatable launch.

  • One intake spec and one pipeline template with quality checks built in
  • Model cascades that send only uncertain items to bigger models and people
  • Refresh schedules and drift monitors, plus data formats for new markets
Year-two targetTime and cost to launch a new attribute family cut in half
3
Year three

Built for agents

Publish facts that software can reason over, with the evidence attached.

  • One interface that serves each fact with its confidence and provenance
  • Household restrictions honored in search and in replacements
  • Retailers and brands see and fix their own data problems
Year-three targetMost agent answers about dietary fit cite a verified fact

Where to start

Five problems worth fixing first

Each came up more than once in my conversations with the team. Each fix is deliberately simple.

#ProblemSimple fix
1Every new attribute is built by hand, and demand keeps growing from search, replacements, health and agents.A standard intake spec plus one reusable pipeline template with quality checks built in, so the tenth attribute costs less than the first.
2Health tags such as gluten-free and allergens need near-perfect precision, and there is no ground truth to measure them against.A small hand-labeled golden set per attribute that serves as the release gate.
3Nobody can easily explain why a value won. Precedence differs by attribute and by retailer.Record the winning source and the rule that picked it every time a value is written. The same record answers ops escalations and retailer questions.
4Teams that consume catalog data cannot tell what a field means or how far to trust it.An attribute card for each family, with confidence published next to every value so each consumer sets its own threshold.
5Shipped pipelines decay, and some incidents return months later because the fix treated the symptom.A refresh schedule and quality monitor per attribute, plus a recurrence tracker that moves repeat issues up the roadmap.

Operating principles

How the work would run

  • Measure before you ship. Every attribute family gets a golden set and a release bar before launch.
  • Confidence travels with the value. Consumers decide their own threshold.
  • Every value can explain itself. Lineage is written at the same moment as the value.
  • Fix the class of problem the second time it appears. A repeat incident earns a root-cause slot on the roadmap.
  • Keep the vision current. Refresh it each planning cycle and walk every new leader through it.
First 90 days

How I would start

  1. Weeks 1 to 4. Listen. Map how each consuming team uses catalog data, and measure two high-stakes families against a quick golden set.
  2. Weeks 5 to 8. Stand up golden sets and lineage logging for allergens and one medical diet.
  3. Weeks 9 to 12. Write the vision doc with the team, review it up the chain, and set year-one targets against the measured baselines.
Risks and open questions

What could change the plan

Rebuild or extend

The current model is about ten years old. Before deciding either way, I would stress-test it against the hardest upcoming use cases and price each gap.

Health claims need legal review

Subjective tags change meaning over time. Definitions should be reviewed with legal before an attribute ships.

Model cost at catalog scale

Frontier models are expensive across millions of products. Cascades and caching keep the cost bounded.

Foundation work competes with new attributes

An explicit split of capacity each quarter keeps both moving and makes the trade visible.
