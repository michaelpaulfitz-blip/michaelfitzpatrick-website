Growth and Best Practices

Home base for everything that makes working with Claude Code better across every project, not just one. Standing conventions, research findings, and the running list of improvements worth making.

Maintained from the central_dev_management_and_improvements directory, which exists purely for cross-project work. Individual projects keep their own notes; anything that should apply everywhere gets promoted here.

What lives here

Four kinds of content, and the plan is to keep it to four.

Standing conventions

The global rules Claude Code follows in every project: tone, response style, working agreements. Source of truth is the global settings file; this page records what is in it and why.

Research findings

Write-ups on Claude Code capabilities worth adopting: skills, hooks, memory, plugins, workflows. Reviewed together, then either adopted or filed.

Open threads

Improvements that have been identified but not yet made, with enough context to pick them up cold in a fresh session.

Changelog

A dated log of what changed at the global level, so drift is visible and nothing gets applied twice.

Where the global settings live

Roughly 90% of Claude usage happens in Claude Code rather than claude.ai chat, so the Claude Code global file is the single tone control that matters. The claude.ai profile preferences are a separate system and are intentionally left alone.

LayerPathScopeNotes
Global instructions C:\Users\Micha\.claude\CLAUDE.md Every Claude Code session, every repo Currently holds the three Response Style bullets: casual tone with humor, concise and non-repetitive, end long answers with a Bottom line.
Per-project memory C:\Users\Micha\.claude\projects\<project>\memory\ That project only Does not carry across projects. Anything saved here that should be universal has to be promoted to the global file by hand.
Project instructions <repo>\CLAUDE.md One repo Codebase-specific conventions. Not the place for tone or working-style preferences.
